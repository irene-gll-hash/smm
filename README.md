# SMM-сервис КИФА

Закрытый Python-сервис управляет подготовкой SMM-контента через Telegram. Он использует исходящие соединения к Telegram Bot API, Google Drive, Google Sheets и API языковой модели. Входящий webhook и открытый порт не требуются.

## Что реализовано

- ручной запуск разбора выбранного периода на Google Drive;
- чтение документов, таблиц, PDF, текстов и доступных ссылок;
- формирование разбора материалов и предложений контент-плана;
- согласование и ручная правка плана в Telegram;
- создание текстов только по одобренным пунктам;
- отдельные режимы для внепланового и тестового поста;
- ручная замена полного текста без вызова ИИ;
- переписывание по инструкции с вызовом ИИ;
- добавление и полная замена медиа через Telegram либо Drive;
- обязательное повторное согласование после изменения текста, плана или медиа;
- отдельное решение о добавлении одобренного поста в `Эталоны`;
- предпросмотр поста с изображениями и видео;
- немедленная и отложенная отправка только в тестовый Telegram-канал;
- восстановление очереди после перезапуска и защита от повторной обработки Telegram update.

В MVP нет критика, RAG и автоматического обучения. Текст пишет одна настроенная модель, окончательное решение принимает человек. Подключение официальных каналов и других соцсетей оставлено за адаптерами следующего этапа; текущий publisher знает только тестовый Telegram-канал.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `telegram.py` | long polling управляющего бота, меню, кнопки и диалоги |
| `pipelines.py` | разбор, план, версии текста, медиа, эталоны и публикация |
| `publisher.py` | отдельный транспорт бота-публикатора в тестовый канал |
| `google_workspace.py` | Google Drive и Google Sheets |
| `db.py` | очередь, сессии, решения и журнал публикаций в SQLite |
| `jobs.py` | выполнение немедленных и отложенных заданий |
| `prompts.py` | анализатор, планировщик и редактор |

## Google Workspace

Сервис работает от имени пользователя через OAuth 2.0 Desktop app. Пользователю нужны права редактирования таблицы и корневой папки Drive. В проекте Google Cloud включите Google Drive API и Google Sheets API, настройте экран согласия OAuth (в режиме Testing добавьте пользователя в Test users). Сохраните JSON клиента типа Desktop app в `secrets/google-oauth-client.json`.

Запрашиваются scopes `https://www.googleapis.com/auth/drive` и `https://www.googleapis.com/auth/spreadsheets`. Обязательные листы и заголовки описаны в `docs/SHEETS_SCHEMA.md`.

Папка периода содержит произвольные тематические подпапки. Их названия задаёт человек. Внутри периода сервис создаёт подпапку даты и одну видимую папку конкретного поста. Файлы `01_...`, `02_...` задают порядок медиа. ИИ не распознаёт и не перегенерирует изображения и видео.

## Telegram

Используются два разных бота:

1. управляющий бот — доступен сотрудникам и не является администратором канала;
2. бот-публикатор — имеет право публикации только в тестовом канале.

Главное меню содержит: разбор материалов, формирование и согласование плана, подготовку и согласование текстов, внеплановый пост, тестовый пост, экспорт и статус очереди.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
cp .env.example .env
# Заполните .env и положите OAuth-клиент в secrets/
qifa-google-auth
docker compose up -d --build
docker compose logs -f qifa-smm
```

Первичную авторизацию запускайте на компьютере с браузером из корня проекта. Команда `qifa-google-auth` открывает браузер и временный callback-сервер на localhost, ждёт до 5 минут и сохраняет токен в `secrets/google-oauth-token.json`. Остальные настройки сервиса (Telegram и LLM) для этой команды не нужны. URL авторизации и секреты в консоль и логи не выводятся. Механизм входа использует [InstalledAppFlow](https://googleapis.dev/python/google-auth-oauthlib/latest/reference/google_auth_oauthlib.flow.html).

Пути задаются `GOOGLE_OAUTH_CLIENT_FILE` и `GOOGLE_OAUTH_TOKEN_FILE`; относительные пути считаются от текущего каталога. Старый `GOOGLE_SERVICE_ACCOUNT_FILE` больше не используется. Compose задаёт контейнерные пути и монтирует всю папку `secrets/` с правом записи: access token обновляется через refresh token и атомарно сохраняется, в том числе во время работы. При отсутствии или отзыве токена сервис сообщает о необходимости повторить `qifa-google-auth`, браузер при запуске сервиса не открывается. Перед повторной авторизацией остановите сервис, затем запустите снова.

Папка `secrets/` уже исключена из Git. Файл токена создаётся с правами `0600`. На Linux перед запуском Docker обеспечьте доступ пользователю контейнера (UID 10001): `sudo chown -R 10001:10001 secrets`, `sudo chmod 700 secrets`. Для повторного локального входа сначала верните владельца папки и файлов своему пользователю. Не делайте токен общедоступным. Для запуска без Docker после авторизации выполните `qifa-smm` (задайте доступный локальный `DATABASE_PATH`).

Проверка тестов: `python -m unittest discover -s tests -v`. Тесты используют поддельные credentials и не запускают браузер или Google API.

Полученные Telegram-события сохраняются в SQLite до продвижения offset. Ошибка ответа
на callback не отменяет действие. При технической ошибке обработки событие остаётся
в локальной очереди и повторяется, в том числе после перезапуска; следующие события
ждут устранения ошибки. Явный отказ (например, устаревшая версия) сообщается пользователю.
Это обеспечивает сохранность полученных событий, но не гарантирует однократность
внешних изменений при сбое между выполнением действия и записью результата.

Контейнер не публикует порты. Для локальной проверки без расходов можно временно указать `LLM_MODE=stub`; публикация в тестовый канал при этом остаётся реальной, поэтому для проверки интерфейса без отправки не нажимайте кнопку публикации.
